# OptiScaler NR susemi-next-ko r3 (wilsjo2 v0.8.8 기반)

이번 r3 패키지는 상류 v0.8.8의 NR 조명·색상 재구성 모드를 우리 트리에 올리고, XeFG 프레임 생성이 켜진 상태에서 NR이 화면에 실리지 않던 배치 문제를 고친 누적 릴리스입니다. 한국어 메뉴 번역은 새로 생긴 문자열까지 반영했고, 번역 문자열 추출기의 커버리지 가드도 함께 손봤습니다.

## 이전 릴리스에서 달라진 점

### 1. NR 조명·색상 모드 (Transfer=3, Transfer=4)

모델 해상도를 100% 아래로 낮추면 RGB 잔차를 그대로 리사이즈하는 과정에서 어두운 머리카락과 밝은 피부 경계에 밝은 테두리가 생길 수 있습니다. 새 경로는 상대 조명 이득과 색도 변화를 따로 리사이즈한 뒤, 전체 해상도 프록시에서 모델 출력을 다시 구성합니다. NR 메뉴에서 모델 해상도를 100% 아래로 두고 고르면 됩니다.

- **조명 + 색상**: 바이리니어 재구성, `[DlssNr] Transfer=3`. DX12와 네이티브 Vulkan 처리 경로에서 쓸 수 있습니다.
- **조명 + 색상 + DLSS**: 같은 필드를 전용 DLSS SR로 확대, `Transfer=4`. 업스케일 이후 DX12 처리 경로가 필요합니다(기존 DX12 브리지 포함). 게임 업스케일러 이전 단계와 네이티브 Vulkan에서는 쓸 수 없습니다.

기본값은 그대로 Matched residual(`Transfer=1`)입니다. 클래식, Matched residual, Matched residual + DLSS는 기존 알고리즘을 유지하고, 네이티브/슈퍼샘플 모델 처리는 새 재구성을 거치지 않습니다. 어두운 테두리를 줄이는 것이 목적이고, NR 출력 자체에 이미 들어간 아티팩트를 없애지는 못합니다.

### 2. XeFG 아래에서의 NR 배치 수정

XeFG가 프레임을 생성하는 동안 NR 결과가 표시되는 프레임에 실리지 않던 문제를 고쳤습니다. 애플리케이션 Present 경로에서 NR 합성을 한 번만 수행하도록 소유권을 넘기는 방식(owned application-frame handoff)으로 바꿨고, 같은 (generation, frame) 식별자를 두 번 처리하지 않습니다. 합성을 건너뛰더라도 캡처 구간은 항상 닫히고, 스왑체인 재생성 시 식별자가 초기화됩니다.

함께 들어간 것:

- 새 진단 토큰. 콜드 스타트에 `NR_XEFG_ROUTE`, 적용 시 `NR_XEFG_APPLY`, 거부 시 이유를 붙인 `NR_XEFG_SKIP`, 표시 후 `NR_XEFG_PRESENT`. 색 공간이 SDK가 지원하는 범위를 벗어나면 `NR_XEFG_ROUTE_REFUSED`가 찍힙니다.
- 앱이 색 공간을 알려주는 `SetColorSpace1` 경로를 XeFG 프록시 스왑체인에 연결했습니다. 이 훅은 기존에 없던 것이라 새로 추가했습니다.
- 번들된 XeFG SDK는 HDR10(`R10G10B10A2_UNORM`)만 지원합니다. FP16/scRGB는 지원하지 않고 거부합니다.
- 프레임 생성 끄기는 우회로가 아닙니다. FG를 켠 상태에서 확인하세요.

### 3. 한국어 카탈로그

카탈로그가 835개에서 **848개**로 늘었습니다. 새 NR 문자열(`Lighting + colour`, `Lighting + colour + DLSS`)과 다시 쓴 도움말 문구를 번역해 넣었고, 생성기와 검증기(엄격 모드, 차단 경고 0)를 모두 통과했습니다.

### 4. 추출기 커버리지 가드 수정

리터럴 첫 인자로 호출된 문자열이 추출되지 않아도 가드가 조용히 넘어가던 오프바이원 버그를 고쳤습니다. 추출 결과 수는 그대로(871개)이고, 이제 덮이지 않은 호출이 있으면 이름을 찍고 종료 코드 1로 실패합니다.

두 zip 모두 안에 든 `SHA256SUMS.txt`가 100% 일치합니다(A 51/51, B 55/55). 압축을 풀어 다시 계산하는 방식과 zip 안을 직접 스트리밍하는 방식, 두 가지로 확인했습니다.

A와 B는 NR과 XeFG 코드가 같습니다. B는 A에 RTX 20/30용 SM86 MFG 페이로드 네 개를 더한 것이고, 두 zip에서 `OptiScaler.dll`만 다시 링크된 결과로 바이트가 다릅니다. 나머지 공유 멤버 50개는 바이트 단위로 같습니다.

## 검증 요약

- 빌드: Release x64와 Release-RTX40-MFG 두 flavour 모두 exit 0.
- NR 프리릴리스 스위트: exit 0. 새 300개 픽스처 리사이즈 스모크까지 포함해서 돌았습니다(최대 재구성 오차 0.0000018). 나머지 게이트 스위트도 15/15 exit 0.
- XeFG 핸드오프 시임: 11 케이스 / 74 체크 그린. 두 번 돌려 바이트까지 같았습니다.
- 델타 분류(r1 기준): A는 ADD 2개 허용 / 예외 0, B는 ADD 6개 허용 / 예외 0, 두 run 모두 MODIFY 10(허용 8 + 설치기 2), IDENTICAL 40, DROPPED 16(소유자 지정 슬림 목록 전량, 그 외 드롭 0). 무-드롭 게이트, 설치기 2건(도구의 고정 허용 목록 밖), r1 기준으로 앞선 6키를 잡는 ini 핀 때문에 도구 종료 코드는 1이고, T13 재패키징 델타(직전 v11 zip 대비)는 ADD 0 / DROP 0 / MODIFY 6(Config.md, INSTALL-KO.md, dll, ini, 노트 스냅샷, sums)로 PASS입니다. 실패 시드 세 개(여분 파일 추가, `setup_windows.bat` 바이트 한 개 변조, 기존 INI 키 `[FrameGen] Enabled` 삭제)는 모두 이름을 찍고 exit 1로 걸렸습니다.
- 패키지 안 `OptiScaler.dll`을 직접 열어 `NR_XEFG_ROUTE`, `NR_XEFG_ROUTE_REFUSED`, `NR_XEFG_APPLY`, `NR_XEFG_SKIP`, `NR_XEFG_PRESENT` 토큰과 새 한국어 라벨(`조명 + 색상`, `조명 + 색상 + DLSS`)이 들어 있는지 확인했습니다. A와 B 양쪽 모두 있습니다.

## 하드웨어 공백 (여기서 검증하지 않은 것)

이 장비에는 RTX 20/30 실기 GPU가 없고, XeFG/HDR 세션도 없습니다. 그래서 아래 두 가지는 이번 릴리스에서 검증되지 않았습니다.

- **SM86 페이로드의 실제 동작**: RTX 20/30 카드에서의 배수와 성능. 20/30 경로는 로더, 설정, 패키징, 장착 순서 수준까지만 확인했습니다.
- **게임 안에서의 XeFG 배치**: XeFG 6x에서 NR 효과가 보이는지, 깨끗한 화면과 편집된 화면이 번갈아 나오지 않는지, HUD가 온전한지, 리사이즈와 로딩 구간이 안전한지.

최종 인게임 확인은 소유자가 직접 합니다. 확인 절차와 롤백 방법은 `.omo/evidence/nr-xefg-088-release/15/ACCEPTANCE-KO.md`에 정리해 두었습니다.

## 설치

1. 게임 폴더에 zip을 풀어 넣습니다. RTX 20/30 MFG 언락을 쓰려면 B를, 아니면 A를 쓰세요.
2. `setup_windows.bat`을 실행해 설치합니다.
3. 다른 OptiScaler DLL은 덮어쓰지 마세요.
4. 문제가 생기면 A로 되돌리면 됩니다. A에도 XeFG 배치 수정은 들어 있고, SM86 페이로드만 빠집니다.

이 노트는 A와 B 두 패키지 모두에 `docs/RELEASE-NOTES-r3-KO.md` 파일로 포함됩니다.
